# 长株潭「标点地图」文旅小程序 · 功能说明

**一句话**：一张长株潭地图，把值得去的点标出来；点开有攻略，能按精选路线逛，到了能打卡。

- 性质：大学生创新创业训练项目作品，**不追求上线**，追求"能演示、能讲清楚、数据是真的"
- 技术：微信原生小程序（WXML/WXSS/JS），无框架、无构建、无后端
- 当前版本：**0.8.0**（体验版）
- 数据规模：**51 个点位**（湘潭 26 / 长沙 16 / 株洲 9）、**7 条路线**（湘潭 3 / 长沙 2 / 株洲 2）
- 坐标与交通：全部来自高德 Web 服务接口（GCJ-02，与小程序地图同一坐标系）
- v0.6.0 新增「我的行程」：每个点位都能点「＋」自己挑、自己排序，看步行 / 公交 / 打车三种耗时，最后在地图上连成一条线；排序面板可以随时隐藏
- v0.7.0 新增「搜索点位」：地图页右上 🔍 与行程页面板顶部都能搜（名称 / 标签 / 城市 / 分类 / 拼音 id），点搜索结果直接加入或移出「我的行程」，跨城市点位也能搜到
- v0.8.0 新增「酒店」分类（6 家，湘潭 / 长沙 / 株洲各 2 家），和景点、美食一样能搜、能加进行程；搜索结果改成**先看介绍卡片、再决定加不加**（简介 / 开放时间 / 地址 / 标签都在卡片上）

## 一、产品定位

做的是"**标点 + 路线 + 打卡**"三件事，不做第二个大众点评：

| 不做 | 做什么 |
|---|---|
| 不堆商铺、不做点评 | 只收录"到了能玩、能拍、能吃"的点，每城 30–50 个 |
| 不做全城公交查询 | 只给精选路线上"相邻两站怎么走"的真实交通 |
| 不做社交、不做云同步 | 打卡只记本机，够演示"足迹"概念 |

目标用户：周末想逛长株潭、但不知道去哪的本地学生 / 外地来客。

## 三、页面与交互详解

### 3.1 地图页（`pages/map`）

**结构**（自下而上）：

```
<map>  全屏地图，marker / polyline 都由 data 驱动
顶部面板（绝对定位）
  ├─ 城市 pill（湘潭 ▾） + 标题「标点地图」 + 「全部 · 26 个点」 + 右上「🔍」搜索
  ├─ 搜索浮层（搜点位 → 介绍卡片 → 加入行程 / 查看行程）
  └─ 分类 chips（全部 / 景点 / 古镇街区 / 红色 / 学府 / 美食 / 酒店）
底部（绝对定位）
  ├─ 点位横向卡片列表（名称 / 分类 / 时长 / 右上「＋」加入行程）
  ├─ 弹出的点位卡片（名称 / 分类 / 时长 / 一句话 / 备注 / 导航按钮 / 标题旁「＋ 行程」）
  └─ 左下「📋 我的行程 N」+「🧭 精选路线」 + 右下「◎」定位
```

**交互链路**：

1. 点 marker 或底部列表卡片 → 底部弹出卡片（**地图视野不动**，避免误触抖动）
2. **上滑卡片 / 点标题 / 点把手** → 展开成整页详情（简介、地址、开放时间、距你、打卡按钮），像小红书那样
3. 下滑或点 × → 收起到卡片；再关闭则回到地图列表
4. 点「导航」→ `wx.openLocation` 调起微信地图；点「到这里打卡」→ 面板内直接打卡
5. 点地图空白处 → 关闭面板
6. 点 marker 后 300ms 内的地图 tap 会被忽略（微信会同时触发 `markertap` 和地图 `tap`，不加时间窗会导致卡片一闪而过）
7. 每个点位都能加入「我的行程」：列表卡片右上「＋」、面板标题「＋ 行程」、详情页头图右上「＋ 加入行程」，加入后变成「✓ 第 N 站」，再点移出
8. 点右上「🔍」→ 搜索浮层：输入即出结果（名称 / 标签 / 城市 / 分类 / 拼音 id），点结果**先弹出介绍卡片**；卡片底部「＋ 加入行程」/「✓ 已加入 · 第 N 站」，也可「查看详情」，左上角「‹ 结果」回列表；浮层底部「查看行程 ›」；点空白处关闭

> 地图页不再跳「详情页」：所有信息在面板里就能看完、能打卡。
> 独立详情页 `pages/detail` 保留给**路线页跳转**和**分享深链**（`?focus=<id>`）。

**分类与配色**（`data/places.js` 的 `CATEGORIES`）：

| key | 名称 | emoji | 打卡半径 | 湘潭 / 长沙 / 株洲 |
|---|---|---|---|---|
| `scenic` | 景点 | 🏯 | 600 m | 11 / 9 / 5 |
| `oldtown` | 古镇街区 | 🏮 | 800 m | 4 / 2 / 0 |
| `red` | 红色 | 🚩 | 1200 m | 4 / 0 / 2 |
| `school` | 学府 | 🎓 | 1500 m | 3 / 1 / 0 |
| `food` | 美食 | 🍜 | 300 m | 2 / 2 / 0 |
| `hotel` | 酒店 | 🏨 | 300 m | 2 / 2 / 2 |
| 合计 | | | | **26 / 16 / 9（51）** |

**颜色怎么对应**：分类 chip 左边的小圆点就是图例——青色=景点、褐色=古镇街区、红色=红色、蓝色=学府、橙色=美食、紫色=酒店，和地图上 marker 的底色一致；底部卡片里的分类色块也是同一套颜色。

**点位气泡**：缩放到一定级别、点位之间不重叠时，点旁会出现「emoji + 名称」气泡。
规则是「放大到不重叠才显示」：小于 13.5 级不显示；两个点屏幕间距小于 128px 时，这一对都不显示，避免糊在一起。
实现用的是 marker 原生 `callout`（`display: 'ALWAYS'`），缩放级别通过 `mapCtx.getScale()` 同步——`regionchange` 的 `e.scale` 在部分机型拿不到，之前气泡完全不出就是这个原因。
> 需要真实照片的话要另做「图片 marker」（按点位生成小图）或自定义 callout，原生 callout 只能放文字。

**筛选行为**：

- 选「红色」时，自动 `includePoints` 到韶山、乌石那片（湘潭的红色点位都在西南远郊）
- 选「全部」恢复城市默认视野
- 切换分类、切换城市都会重新渲染 marker，视图跟着调整

### 3.3 点位详情

两种形态，内容一致：

| 形态 | 入口 | 说明 |
|---|---|---|
| 地图页内嵌面板 | 点 marker / 底部列表 | 收起是卡片，上滑展开成整页，可直接打卡 |
| 独立详情页 | 路线页点「看点位详情」、分享深链 `?focus=` | 单独一屏，带导航标题 |


**结构**：头图（分类色块 + emoji + 名称 + 一句话 + 标签）→ 事实信息（分类 / 地址 / 开放时间 / 建议时长 / 距你）→「关于这里」→「备注或补充」→ 底部「导航」「到这里打卡」。

**自动定位**：进页面先 `wx.getLocation` 一次，把到目标的距离写在「距你」那行，右边「刷新」可重新定位。

| 状态 | 显示 | 打卡按钮 |
|---|---|---|
| 在范围内 | `1.0 公里 · 在打卡范围内`（绿） | 「到这里打卡」直接成功 |
| 超出范围 | `2.0 公里 · 超出 1.5 公里 范围` | 弹「还差一点」，可选**手动打卡** |
| 没给权限 | `定位没打开（点这里开启）` | 引导去设置，或手动打卡 |
| 距离 > 30 公里 | — | 弹窗额外提示"可能是模拟定位"（调试用） |

### 3.4 打卡机制

- 判定半径按分类给（见 3.1 分类表），单个点位可用 `radius` 字段覆盖
- 距离用 Haversine（`utils/geo.js`），单位米
- 成功记录写 `wx.storage`：`{ at: 时间戳, distance: 米, manual: 是否手动 }`，key 为 `checkin:<id>`
- 同一台设备再进详情页，显示「✅ 已打卡 + 时间」，按钮变绿
- **没有云端**：换手机/清缓存后记录消失，演示时要提前说明

**卡片规则**：同一时间只显示一张卡片（交通段卡片 / 地点卡片互斥，统一走 `setCard()`），

**两种点击方式**（都保留）：

| 操作 | 事件 | 结果 |
|---|---|---|
| 点站点（数字 marker / 底部站点卡片） | `bindmarkertap` | 卡片显示这个点的「上一段 / 下一段」，带「看点位详情」按钮 |
| 点路线（折线本身或附近） | `bindpolylinetap`（3.1.0+）→ `bind:tap` 坐标兜底（2.9.0+）→ `bindpoitap`（点在自带 POI 上） | 卡片显示这一段：交通方式、起终点、距离、时间 |

|---|---|
| 10.5 – 12.5（看全城） | 500 m |
| 14 | 463 m |
| 16（看街区） | 116 m |
| 18（贴脸） | 60 m（下限） |

匹配算法是**点到线段垂距**（不是到最近顶点），所以长直线段中间也能点中。

### 3.6 我的行程页（`pages/trip`）

**结构**：

```
<map> 编号 marker（1..N）+ 每段交通的折线 + 交通小图标（带「N 分」时间标签）
顶部：‹ 返回 + 「我的行程」+ 统计（点位 / 游玩 / 在途 / 总耗时 / 里程）+ 「隐藏排序 / 显示排序」
底部：可拖动的排序面板
  ├─ 搜索框（搜景点 / 美食 / 酒店 → 介绍卡片 → 加入 / 移出）
  ├─ 第 N 站（把手 ⠿ / 序号 / 名称 / ▲▼ / ✕）
  ├─ 相邻两点之间的交通段（步行 / 公交地铁 / 打车 三种分钟数，点选切换）
  └─ 「＋ 加点」「清空」
```

**入口**：地图页左下「📋 我的行程 N」（有行程才带数字）、点位列表卡片右上「＋」、点位面板标题「＋ 行程」、独立详情页头图右上「＋ 加入行程」、地图页右上「🔍」搜索、行程页面板顶部搜索框。
加进去后按钮变成「✓ 第 N 站」，三处状态同步（`onShow` 时重新读一遍本机存储）。

**搜索加点**（`components/place-search` + `utils/search.js`）：输入关键词即时过滤，命中优先级「名称完全相同 > 名称前缀 > 名称包含 > 标签 > 城市 / 分类 / 地址 / 简介 / 拼音 id」。点一条结果**先出介绍卡片**——简介、建议时长、开放时间、地址、标签，右上角显示已加入的站号；卡片底部「＋ 加入行程」/「✓ 已加入 · 第 N 站」和「查看详情」，点「‹ 结果」回列表。加入 / 移出都走 `trip.toggle`，与地图页「＋」状态一致。搜不到时提示换关键词；行程空时面板里也有「🔍 搜索点位」入口。

**交通耗时怎么算**（`utils/travel.js`）：

| 方式 | 公式 | 说明 |
|---|---|---|
| 步行 | 直线 × 1.28 道路系数 ÷ 74 m/min | ≈ 4.4 km/h，和精选路线里的实测步行段吻合 |
| 公交 / 地铁 | 道路里程 ÷ 200 m/min + 10 分钟候车 | 含等车、换乘；不足 1 km 会提示「这段走更划算」 |
| 打车 | 道路里程 ÷ 430 m/min + 1 分钟 | 含少量红绿灯与上下车 |

- **实测优先**：`data/routes.js` 里出现过的同向路段（比如万楼→文庙、岳麓书院→岳麓山）直接用实测距离和分钟数，列表里标「实测」；其余标「估算」
- **推荐方式**：有实测用实测；否则 < 1.2 km 步行、< 6 km 公交地铁、更远打车
- 行程存本机 `wx.storage`，key `trip_v1`：`{ ids: [...], modes: { '万楼|文庙': 'taxi' }, updatedAt }`，`modes` 只记用户改过的段

**面板交互**：

- 默认半屏。上滑到全屏、下滑收起到半屏、再下滑隐藏；隐藏后地图上只剩一条「显示排序」细条
- 拖「⠿」排序时列表实时让位、上方提示「松手放到第 N 位」；松手后写回存储，地图图钉重新编号
- 切换某段的交通方式，折线颜色（青绿步行 / 蓝公交 / 褐打车）和顶部「在途」时间立即更新
- 没有点位时显示「还没挑点位」+「🔍 搜索点位」+「去地图挑点位」：前者展开面板并聚焦搜索框，后者直接跳回地图页

> 排序面板用 `translateY` 三段吸附（`hidden` / `half` / `full`）：按住「⠿」拖动时实时跟手，松手按离哪个状态最近就吸附到哪一个。

## 五、技术实现要点

| 点 | 说明 |
|---|---|
| 架构 | 原生小程序 4 个页面：map / trip / routes / detail + 1 个可复用组件（`components/place-search`），外加 3 个数据文件 + 3 个工具模块（travel / trip / search）；无框架、无构建 |
| 坐标系 | 高德返回 GCJ-02，与 `<map>` 一致，**不要混入百度 BD-09** |
| 地图事件 | `bindmarkertap`（点 marker）、`bind:tap`（2.9.0+ 带经纬度）、`bindpolylinetap`（3.1.0+）、`bindpoitap`（点自带 POI） |
| 视野控制 | 只在"切城市 / 切分类 / 切路线 / 未定位"时主动设中心；**不做 `regionchange` 回写**（会抖） |
| 打卡 | `wx.getLocation` + `wx.storage`，不依赖后端；`requiredPrivateInfos: ["getLocation"]` |
| 交通估算 | `utils/travel.js`：直线 × 1.28 道路系数；步行 74 m/min、打车 430 m/min、公交 200 m/min + 10 分钟候车；`data/routes.js` 里出现过的真实 leg 优先（标「实测」） |
| 行程存储 | `utils/trip.js`：`wx.storage` key `trip_v1`，上限 20 个点；读写带 `typeof wx === 'undefined'` 降级，方便在 node 里跑测试 |
| 行程图钉 | 编号图 `assets/marker/num-1..20.png`（`scripts/gen_trip_markers.py` 生成），每段交通用 `leg-walk/transit/taxi.png` 做地图图标 |
| 搜索 | `utils/search.js` 启动时把 51 个点位拼成索引（名称 / 标签 / 城市 / 分类 / 地址 / 简介 / 拼音 id），按权重排序；`components/place-search` 封装「输入框 → 结果列表 → 介绍卡片 → 加入行程」四步，地图页（浮层）与行程页（面板）复用同一个组件，结果状态直接读 `trip_v1` |
| 包体 | 主包约 **1.1 MB**（上限 2 MB）：点位实景图 896 KB、marker 图 76 KB（6 分类 + 20 序号 + 3 交通）、代码约 100 KB |
| 导航 | `wx.openLocation`，带名称和地址 |
| 基础库下限 | 2.9.0（地图点击带经纬度）；点折线需 3.1.0，低版本自动退化为"点站点看两段" |
| 上传 | 微信开发者工具 CLI：`cli upload -v <version>`；上传前跑 `node scripts/check_pages.js` |

## 六、已知限制（如实说明）

1. **没有后端 / 云同步**：打卡只存本机；换设备、清缓存即丢失。云开发未接入。
2. **打卡接口权限未申请**：`wx.getLocation` 正式使用需在小程序后台申请接口权限（"工具-信息查询"类目），目前开发版/体验版可用；演示时建议提前说明，或用手动打卡兜底。
3. **长沙 16、株洲 9 点位偏少**：湘潭 26 个较完整；另外两城刚补，采集表待团队回填。
4. **文案是初稿**：简介/备注由项目组按公开信息撰写，开放时间未逐点核实。
5. **路线是"策划路线"，不是导航**：折线沿真实道路/地铁，但站点顺序是人工设计的；**城际交通（湘潭↔长沙）未做**。
6. **没有图片**：详情页用分类色块 + emoji 代替实拍图（图片会占主包体积，且需要版权）。
7. **"我的页"未做**：足迹/完成度计划中（D6）。
8. **不能发布上线**：个人主体小程序无法选择"旅游-景区服务"类目，只做演示（开发版/体验版），无需备案。
9. **点位密集时会叠**：市区（五一广场、雨湖老城）几个点在地图上重叠，点中的是最上层；可以改用底部列表点。
10. **交通耗时是估算，不是实时路况**：`utils/travel.js` 用固定速度 + 道路系数 1.28 算，只有精选路线里出现过的真实段用实测值（列表里标「实测」）。真实公交方案要接腾讯/高德路线规划接口（需要 key 和配额），本项目没接。
11. **行程只存本机、上限 20 个点**：和打卡一样没有云同步；编号图只做到 20，需要更多就重跑 `python scripts/gen_trip_markers.py 21 40`。
12. **跨城行程只给粗略估算**：行程里可以选别的城市的点，但城际交通（湘潭↔长沙）没有真实 leg，按打车/公交速度直线估，演示时说明即可。
13. **搜索是本地关键词匹配**：不调地图平台接口，只能搜到项目里已有的 51 个点位；支持原名、标签、城市、分类、地址、简介和拼音 id，但**不支持拼音首字母**（如「ylsy」搜不到岳麓书院），也没做联想词和高亮。点位补到上百个后建议改成服务端搜索。
14. **酒店是「示意数据」**：6 家酒店的名称、坐标、地址按公开信息近似填写，没有逐点校准（和景点一样是 GCJ-02 近似值）；建议时长 30 分钟只算「办理入住 + 放行李」，不含过夜。正式使用请用腾讯位置服务坐标拾取器校正。
